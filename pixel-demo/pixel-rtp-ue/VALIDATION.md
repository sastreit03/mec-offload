The server fixture tests never alter the original files. They use the real uploaded
HTTP/WebSocket handlers and scheduler, with a fake inference engine to avoid loading
the GPU model and manually supplied decoded frames/JPEG. They do not execute the
server's GStreamer receiver or RAN gRPC connection.

The following require the Pixel and testbed:

- Full Gradle APK build/signing and installation.
- Camera2 YUV capture and flexible-YUV MediaCodec input support on the actual Pixel.
- Crop/orientation correctness, achievable FPS and bitrate, encoded local decoder
  rendering, observed GOP distances, and foreground/reconnect lifecycle behavior.
- Actual OAI attachment, cellular/PDU routing, RTP/GStreamer decode on the MEC,
  returned HTTP preview over that path, and real Qwen3-VL GPU results.

`tests/test_server_contract.py` and `tests/test_dashboard.cjs` can be rerun. The Java
tests require a JDK and do not require an Android SDK. Source/API compilation is not
an APK build or device validation.
